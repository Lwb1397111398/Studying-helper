# 跨端独立应用与离线同步完成设计

## 背景

目标是让电脑端 Web/FastAPI 程序和 Android APP 都成为可独立使用的一等客户端。两端都能导入或创建学习内容，完成学习、复习、考试和 AI 分析，并通过离线 JSON 同步包在设备之间转移学习进度。

当前代码已经具备第一版基础：

- 后端已有 `backend/app/modules/sync/`，支持导出全部、导出单书、预览导入和覆盖式导入。
- Web 已有 `/sync` 页面和 `frontend/src/api/sync.ts`。
- Android 已有 Room 数据库、同步 DTO、`SyncRepository`、本地导入/导出入口、文档导入、AI 分析和考试模式的基础实现。

本设计收敛后续工作，不引入云同步，不做自动冲突合并。先把离线同步包做成稳定跨端契约，再补齐两端独立学习体验和验证闭环。

## 设计目标

1. 电脑端可独立完成书籍导入、知识拆分、AI 学习、教学、复习、考试、导出笔记和同步包导入/导出。
2. Android 端可独立完成新建/导入书籍、学习知识单元、AI 分析、复习反馈、考试和同步包导入/导出。
3. 同步包在 Web 与 Android 之间双向兼容，能够传递书籍结构、知识单元、掌握度、学习记录、复习/考试记录、教学记录和 AI 分析结果。
4. 导入采用明确的覆盖式策略：同 ID 书籍被目标端整本覆盖，避免半自动合并导致学习进度错乱。
5. 每个实施切片完成后必须运行对应测试/构建，并进行代码质量审查，再进入下一步。

## 非目标

- 不实现云同步、账号体系、设备在线配对或后台自动同步。
- 不实现字段级自动合并或复杂冲突解决。
- 不把 Android 做成 Web 的远程控制器；Android 必须能离线独立使用。
- 不在本轮重构无关模块或改动与同步/独立体验无关的代码。

## 推荐方案

采用“稳定同步契约优先”的路线：

1. 先把 `SyncPackage` 作为 Web 与 Android 的共享数据契约稳定下来。
2. 后端同步模块是契约权威实现，Android DTO 与 Room 实体跟随该契约。
3. Web 同步中心负责可视化导出、预览、覆盖提示和导入结果反馈。
4. Android 同步入口负责系统文件选择器导入/导出，并在本地数据库中覆盖同 ID 数据。
5. 每次扩展 Android 独立功能时，确保新增数据能进入同步包并可由 Web 导入展示。

该方案优先保证“随时转移到另一端继续学习”的核心目标，比先打磨单端 UI 或提前做云同步更可靠。

## 架构

### 后端同步模块

模块边界保持在 `backend/app/modules/sync/`：

- `schemas.py` 定义同步包模型和版本号。
- `service.py` 负责从数据库组装同步包、预览导入影响、覆盖式导入。
- `router.py` 提供 `/api/v1/sync/export`、`/api/v1/sync/books/{book_id}/export`、`/api/v1/sync/preview`、`/api/v1/sync/import`。
- `tests/test_sync_service.py` 覆盖导出、预览和导入行为。

后续修改只在同步模块补充缺失字段、校验和测试，不把同步逻辑散落到业务 router。

### Web 客户端

Web 保持现有分层：

- `frontend/src/api/sync.ts` 封装同步 API。
- `frontend/src/pages/SyncCenter.tsx` 承载同步中心交互。
- 路由使用 `/sync`。
- 侧边栏或首页提供同步入口，避免用户找不到跨端迁移功能。

同步中心需要明确展示：

- 导出全部数据。
- 导出单本书。
- 导入前预览包来源、书籍数量、知识单元数量、掌握记录数量。
- 对将覆盖的本地书籍给出明显提示。
- 导入后展示导入数量和覆盖书籍。

### Android 客户端

Android 保持本地优先：

- Room 是本地数据源。
- `SyncDtos.kt` 与后端 `SyncPackage` 对齐。
- `SyncRepository` 负责 JSON 解析、版本校验、覆盖式导入和导出。
- `StudyViewModel` 负责从系统文件 URI 读写同步包，并把状态反馈到 UI。
- `MainActivity.kt` 使用 Compose 呈现当前基础 UI，后续在不引入过度架构的前提下逐步拆分过大的 Composable。

Android 独立功能按最小闭环推进：导入/新建内容 → 查看书籍/章节/知识单元 → AI 分析 → 复习反馈 → 考试 → 导出同步包。

## 同步数据流

### Web 到 Android

1. 用户在 Web 同步中心导出全部或单本同步包。
2. Web 下载 `studying-helper-*-sync.json`。
3. 用户在 Android 选择“导入同步包”。
4. Android 校验 `schema_version == "1.0"` 且至少包含一本书。
5. Android 删除同 ID 书籍相关数据，再插入同步包数据。
6. Android 书籍列表和学习进度刷新。

### Android 到 Web

1. 用户在 Android 离线学习、复习、考试或 AI 分析。
2. Android 导出 `source = "android"` 的同步包。
3. 用户在 Web 同步中心选择该 JSON 文件。
4. Web 预览包内容和覆盖影响。
5. 用户确认导入。
6. 后端覆盖同 ID 书籍相关数据，并返回导入统计。
7. Web 刷新书籍列表、学习报告、复习和考试页面。

## 覆盖策略

同步导入始终以书籍 ID 为覆盖边界：

- 目标端存在同 ID 书籍：删除该书籍的章节、知识单元、知识图谱、掌握度、注释、学习记录、复习/考试记录、教学记录和效率记录，再插入来源包数据。
- 目标端不存在同 ID 书籍：直接插入。
- 全量同步包携带每日统计，并按日期覆盖同用户记录；单书同步包不携带每日统计，避免覆盖同一天其他书籍产生的全局累计数据。
- 用户 ID 统一映射为本地单用户 `anonymous`。

这种策略简单、可解释、可测试。用户如果想保留两端分叉数据，可以先分别导出备份，再选择导入方向。

## 错误处理

- 同步包不是 UTF-8 JSON：返回明确错误。
- JSON 无效：返回明确错误。
- 结构不符合 `SyncPackage`：返回结构无效错误。
- 版本不支持：拒绝导入并说明版本号。
- 空同步包：拒绝导入。
- Android 导入失败：通过状态提示展示失败原因，不部分提交。
- Web 导入失败：保留用户选择的文件或提示重新选择，避免误以为已导入。

## 测试与质量门槛

每个实施切片必须满足对应验证：

### 后端

- `cd backend && PYTHONPATH=. pytest app/modules/sync/tests`
- 涉及全局模型或接口时增加相关模块回归测试。

### Web

- `cd frontend && npm run build`
- 对同步中心改动至少人工检查导出、预览、导入结果状态。

### Android

- `cd android && ./gradlew test` 或 `cd android && ./gradlew assembleDebug`
- 如果本机 Java/Android SDK 不满足条件，记录失败原因，并保留可在 Android Studio 中复测的命令。

### 代码质量审查

- 每个切片修改后调用可用代码审查技能。
- 审查关注：同步字段是否丢失、覆盖删除是否完整、跨端 DTO 是否一致、错误提示是否可操作、是否引入无关重构。

## 实施切片

### 切片 1：同步契约完整性审计

目标：确认后端 `SyncPackage`、Web 类型和 Android DTO 字段一致，补齐缺失测试。

验收：Web 导出的包可由 Android DTO 解析；Android 导出的包可由后端预览和导入。

### 切片 2：Web 同步中心体验收敛

目标：让用户明确知道导出什么、导入会覆盖什么、导入后发生了什么。

验收：Web 同步中心可完成导出全部、导出单本、预览 Android 包、导入 Android 包并刷新列表。

### 切片 3：Android 同步入口与本地闭环

目标：Android 导入/导出同步包状态清晰，失败信息可理解，本地学习数据可完整导出。

验收：Android 导入 Web 包后能看到书籍；Android 修改学习进度后导出，Web 可导入并显示进度。

### 切片 4：Android 独立学习能力补齐

目标：确认 Android 新建书籍、章节、知识单元、TXT/EPUB/PDF 导入、AI 分析、复习反馈和考试结果都进入本地库并参与同步。

验收：Android 不依赖 Web 也能创建或导入学习内容并完成一次学习/复习/考试。

### 切片 5：交付前系统回归

目标：运行后端、Web、Android 的可用验证；审查当前 diff；更新路线图和使用说明。

验收：有新鲜验证证据；遗留问题被明确记录为后续计划；没有 in-progress 的任务被宣称完成。

## 交付标准

项目达到可交付状态时必须同时满足：

1. Web 端核心学习流程可运行，并能导入/导出同步包。
2. Android 端可安装运行，并能独立学习、复习、考试和导入/导出同步包。
3. 同一个同步包能在两端双向解析。
4. 覆盖策略和数据丢失风险在 UI 中明确提示。
5. 后端同步测试通过，前端构建通过，Android 至少完成构建或给出环境阻塞证据。
6. 已完成代码审查并处理高置信问题。
