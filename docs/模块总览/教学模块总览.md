# 教学模块总览

> 最后更新：2026-10-28（P5 补建；P6 收尾对 router.py 仅做 EOF 空行清理，无职能面变化，总览内容仍准确）

## 模块职责（一句话)

管理交互式教学会话：v1 走策略化多轮问答（激活→讲解→检查→总结），v2 走单单元资产绑定的服务端状态机（诊断→激活→讲解→练习→评估→修复→反思→排复习）。

## 运作流程（真实数据流）

### 开课（两条路径，同一入口）

`router.py:134 POST /api/v1/teaching/sessions/start` 收 `{book_id, unit_ids, engine}`：

- **v1（默认）**：`service.py` 的 `TeachingService.start_session`——若书有 AID 教学设计（`TeachingDesignModel` + `ModuleMicroPlanModel`），按 AID 重排的 `unit_ids` 开课；否则按 KG 拓扑排序；再否则按请求原序。会话落 `TeachingSessionModel`，首轮提示词由 `strategies.py` 的策略（激活/讲解/检查/总结四阶段，Cornell 笔记贯穿）用 `prompts.py` 模板生成。
- **v2（`engine="v2"`）**：`session_v2_service.py:41 start_session_v2`——前置校验该 unit 必须已有**资产**：`UnitLearningAssetModel.status=="active"` 且 `readiness_status ∈ {teachable, degraded_teachable}`（不满足抛 SessionV2Error ASSET_PENDING/ASSET_INVALID/ASSET_STALE，router 转 400）。通过后从资产 `payload_json` 解析 `UnitLearningAssetPayload`，生成 `plan_snapshot`（objective_ids/assessment_item_ids/asset_id/created_at），落 `TeachingSessionModel`（`state_v2` 初始为 `diagnose`，`asset_id` 绑定）。返回 `{id, engine:"v2", state_v2, asset_id, ...}`。

### v2 推进（服务端掌权）

1. `router_v2.py`（前缀 `/api/v1/teaching/v2`）暴露 v2 会话的推进/作答接口。
2. `state_machine_v2.py:53 transition(state, event, guards)` 是纯函数状态机：状态共 11 个（`prepare/diagnose/activate/explain/guided_practice/assess/repair/reassess/prerequisite_intervention/reflect/schedule_review`），守卫决定分支（如 assess 不达标进 repair，修复后 reasseass）。
3. `v2_consumer.py` 消费资产内容生成教学上下文：`load_v2_teaching_context`（:61）装载讲解/检查/反思各阶段素材；`build_explain_budget_block`（:179）等三个 builder 拼预算化的提示词块；`pick_feynman_mastery_checks`（:266）为 claim 挑费曼式掌握检查题。
4. `hint_ladder.py` 提示阶梯：学生答不出时按梯度给提示而不是直接给答案。

### 复习衔接

v2 会话结束时把结果交给复习模块（`schedule_review` 状态→`review` 模块的 FSRS 调度，见复习模块总览）。

## 入口文件清单

- `backend/app/modules/teaching/router.py`（前缀 `/api/v1/teaching`：start/推进/问答/测试/Cornell 笔记，v1+v2 开课）
- `backend/app/modules/teaching/router_v2.py`（前缀 `/api/v1/teaching/v2`：v2 会话推进）
- `backend/app/modules/teaching/service.py`（v1 会话编排，引用 v2_consumer 判断 `is_v2`）
- `backend/app/modules/teaching/session_v2_service.py`（v2 开课与资产绑定）
- `backend/app/modules/teaching/state_machine_v2.py`（11 状态纯函数状态机）
- `backend/app/modules/teaching/v2_consumer.py`（资产内容消费/上下文构建）
- `backend/app/modules/teaching/strategies.py`、`prompts.py`、`hint_ladder.py`、`schemas.py`

## 对外接口 / 被谁调用

- HTTP：`/api/v1/teaching/*` 与 `/api/v1/teaching/v2/*`（Web `frontend/src/api/teaching.ts`；Android 端有独立离线教学仓库，不走此 HTTP）
- 上游开课依赖：`adaptive_design`（AID 排序）、`learning_assets`（v2 资产前置）
- 下游：`review`（schedule_review）、`sync`（teaching_sessions/teaching_messages 整包搬运）

## 依赖的上游模块

`ai_learning`（单元 AI 分析）、`learning_assets`（UnitLearningAsset）、`knowledge_graph`（拓扑排序）、`adaptive_design`（模块化设计）、`common`（LLM client）

## 关键数据结构

- `TeachingSessionModel`：`unit_ids`（JSON 数组串）、`current_phase`、`status`，v2 另有 `state_v2`/`asset_id`/`completion_status`
- `TeachingMessageModel`：每轮师生消息
- `UnitLearningAssetPayload`：learning_objectives / claims / assessment_items（v2 教学的内容源）

## 已知坑与约束

1. **同步契约已含 v2 三字段（R1a 修复，2026-10-28）**：`sync/schemas.py` 的 `SyncTeachingSession` 现含 `state_v2`/`asset_id`/`completion_status`（默认 None，旧包零破坏）；Android 侧 `SyncDtos.kt`/`TeachingSessionEntity`/Room 3→4 迁移已对齐（见 Android 端侧数据模块总览的对齐清单表）。v2 会话经同步回灌后状态保值。
2. v2 开课硬前置是资产（active + teachable），无 LLM 时规则化管线也能产出（见 AI 学习与精读模块总览），不要假设 v2 必须有 LLM。
3. Web 与 Android 教学不共用路径：Android 是端侧离线仓库，改本模块不影响 Android 教学，但同步字段要对齐。
