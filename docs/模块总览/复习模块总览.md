# 复习模块总览

> 最后更新：2026-10-28（P1 修复：FSRS lapses 遗忘次数全链路 + quality 映射行为变更）

## 模块职责（一句话）

对知识单元做间隔重复复习调度（SM-2 兼容 + FSRS v4）、考试模式、掌握度评估，并把复习数据导出为 Markdown/Anki/康奈尔笔记/思维导图/错题本。

## 运作流程（真实数据流）

用户在 Web/Android 提交一次复习答案后，数据按以下顺序流动：

1. **入口**：`router.py`（前缀 `/api/v1/review`）收到 `POST /api/v1/review/sessions/{session_id}/answer`，`service.py` 的 `submit_answer` 调 `check_answer` 判对错，写 `Question.is_correct`。
2. **读旧状态**：`service.py:67 _get_mastery` 从 `MasteryRecordModel` 读旧记录并转成 pydantic `MasteryRecord`（`schemas.py`，含 `lapses: Optional[int] = None`——legacy 记录可能为 NULL）。`submit_answer` 里 `old_lapses = (mastery.lapses or 0) if mastery else 0` 做空值防御（`service.py:294`）。
3. **算质量分**：`spaced_repetition_v2.py` 的 `SpacedRepetitionV2.quality_from_correctness`（:218）按对错+响应时间+置信度打 0-5 分：答对快=5、正常=4、慢=3、答错快=2、答错慢=1；置信度调整对正确答案保底 3。
4. **FSRS 调度**：`calculate_next_review(quality, rep, ef, iv, lapses=old_lapses)`（:69）走 `_calculate_fsrs`（:129）：
   - `migrate_sm2_to_fsrs(ease_factor, interval, repetitions)` 把 SM-2 参数迁移成 FSRS 状态，`FSRSState(lapses=真实历史遗忘次数)`（不再硬编码 0）；
   - `fsrs.py` 的 `FSRSScheduler.next_review`：`state.reps == 0` 走 `_init_card`（新卡，不计 lapse），否则 `_update_card`——`new_lapses = state.lapses + 1 if grade == GRADE_AGAIN else state.lapses`（AGAIN 才递增遗忘次数）；
   - 质量分到 FSRS 评分的映射 `_quality_to_grade`（:177，**P1 行为变更**）：0-2→AGAIN(1)、3→HARD(2)、4→GOOD(3)、5→EASY(4)。quality≤2 一律 AGAIN 因为 quality=2 只可能来自答错；quality=3 是"答对但困难"对应 HARD。
5. **回写**：`service.py:313` 把 `schedule.lapses` 等塞进 `fsrs_params`，`_upsert_mastery`（:93）写回 `MasteryRecordModel`：已有记录逐字段 `row.lapses = fsrs_params.get('lapses', row.lapses)`（缺 key 保旧值），新记录 `new_record.lapses = fsrs_params.get('lapses', 0)`。FSRS 路径 `review_count` 每次 +1（`ReviewSchedule.repetitions = repetitions + 1`，与 Android 端累计语义一致）。
6. **同步搬运**：`sync/schemas.py` 的 `SyncMasteryRecord` 含 `lapses` 字段，导入为 delete+add 整包重放；Android 端 `ReviewRepository.kt` 的 FSRSState 读/回写 `existing.lapses`（与后端对齐）。

## 入口文件清单

- `backend/app/modules/review/router.py`（API 前缀 `/api/v1/review`）
- `backend/app/modules/review/service.py`（复习会话/提交/考试/导出编排）
- `backend/app/modules/review/spaced_repetition.py`（SM-2 旧算法）
- `backend/app/modules/review/spaced_repetition_v2.py`（统一调度接口，默认 FSRS）
- `backend/app/modules/review/fsrs.py`（FSRS v4 纯算法：FSRSState/FSRSResult/FSRSScheduler）
- `backend/app/modules/review/schemas.py`（MasteryRecord 等契约）
- `backend/app/modules/review/exporters/`（cornell/markdown/anki/mindmap/wrong_answers 五个导出器）

## 对外接口 / 被谁调用

- HTTP：`/api/v1/review/*`（Web 前端 `frontend/src/api/learning.ts` 调用）
- 被 `teaching` 模块的掌握度评估间接依赖（`mastery_evaluator.py`）
- 同步链：`sync` 模块整包搬运 `MasteryRecord`（含 lapses/stability/difficulty/algorithm）

## 依赖的上游模块

`common`（LLM client、错误）、`db/models.py`（MasteryRecordModel）、`user_storage`（书籍/单元归属）

## 关键数据结构

- `MasteryRecordModel`（DB）：`ease_factor`/`interval_days`/`review_count`（SM-2 兼容）+ `stability`/`difficulty`/`lapses`/`reps`/`scheduled_days`/`algorithm`（FSRS）
- `FSRSState`：stability/difficulty/elapsed_days/scheduled_days/reps/lapses/last_review
- `ReviewSchedule`：下次复习时间/间隔/质量/掌握度变化 + FSRS 专用 stability/difficulty/lapses 等

## 已知坑与约束

1. **历史 lapses 数据不可恢复**：修复前 FSRS 从未正确累积 lapses（永远 0 或丢失），存量记录的遗忘次数无法回填，需重新学习积累或人工修正。
2. **旧同步包缺 lapses 字段导入会清零旧值**：sync 导入是整包 delete+add 重放（所有字段均如此），旧版包不含 lapses 时按 schema 默认清 0——处理决策与风险接受状态见 P6 风险登记（`docs/当前进度.md`），是否改契约保留旧值属老板决策项。
3. SM-2 兼容口径：quality 0-2 均为失败语义（AGAIN）；`ease_factor`/`interval_days`/`review_count` 字段保留，旧数据可继续用 SM-2 路径。
4. 已知相邻缺陷（未修）：`service.py` 经 `migrate_sm2_to_fsrs` 从 ef/iv 重估 stability，未直通存量 stability/difficulty——影响数值精度，不影响 lapses 记账正确性。
